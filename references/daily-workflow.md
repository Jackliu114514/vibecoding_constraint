# 开发操作手册（一页纸版）

> 这份是**开发时看的**。完整方法论见 `vibecoding-规范开发方案.md`，本手册只回答一件事：需求来了，我下一步做什么。

---

## 一句话原则

**每次只推进一张任务卡；AI 先说清楚要做什么，你确认后才让它动手。**

---

## 5 步操作序列（每个任务都走这 5 步）

| 步骤 | 你做什么 | 用哪个文件 | 耗时 |
|---|---|---|---|
| 1. 写需求卡 | 填四要素：上下文 / 目标 / 范围 / 验收 | 方案附录 B1 模板 | ~10 分钟 |
| 2. AI 复述 | 贴需求卡给 AI，加一句"先复述、列歧义、别写代码" | `templates/AGENTS.md` 自动生效 | ~3 分钟 |
| 3. 拆任务 | 每张卡只做一件事、可独立验证、diff ≤ 400 行 | 方案附录 B3 模板 | ~10 分钟 |
| 4. AI 实现 | **一次只贴一张任务卡** + 相关 ADR；边界写死 | `templates/AGENTS.md` | 自动 |
| 5. 过关卡 | AI 自检 → 你按评审清单看 → 用 PR 模板提交 | 方案附录 A3/A4 + B5 | ~5 分钟 |

### 30 秒版（贴显示器上）

```
需求四要素 → AI 复述确认 → 拆原子任务 → 贴卡实现 → 走关卡提交
```

全程只碰 4 个入口：**需求卡 / 任务卡 / AGENTS.md / PR 模板**。详细方案日常不用翻。

---

## 走一遍：以"订单列表按创建日期筛选"为例

### 第 1 步：写需求卡（人，10 分钟）

```markdown
REQ-023：订单列表按创建日期筛选
上下文：订单列表目前只支持状态筛选，运营每天要翻页找某天的订单
目标：运营 3 秒内定位指定日期的订单
范围：内 = 日期区间筛选；外 = 不改导出、不改列表列
验收：Given 选择 11-01 至 11-05
      When 点击筛选
      Then 列表只显示该区间订单，分页总数正确
约束：沿用现有分页组件，不引入新依赖
```

### 第 2 步：让 AI 复述（3 分钟）

把上面的卡贴给 AI，加一句：

> "先复述你的理解，列出歧义点，**不要写代码**。"

AI 应该问出这类问题：区间含不含端点？按哪个时区？是否影响导出？
你回答 → **回填需求卡** → 说"确认，开始拆解"。

> 这一步是整个流程里投入产出比最高的动作。AI 猜错的成本，在这里是三句话；到了代码里就是数百行返工。

### 第 3 步：拆任务（10 分钟）

```markdown
TASK-101：定义筛选参数类型与校验规则（约 50 行）
TASK-102：列表查询接入筛选条件（依赖 101，约 120 行）
TASK-103：补单测覆盖端点、非法日期、总数正确（依赖 102）
```

每张卡写清：**允许改什么、禁止改什么、怎么算完成**。

### 第 4 步：逐张让 AI 实现

> "先读 `AGENTS.md` 和 `ADR-0003`，然后执行 TASK-101。
>  允许改动：`src/order/filter.ts` 及其测试。
>  禁止改动：数据模型、依赖清单。
>  信息不足先问我，不要自行假设。"

做完一张，过一次关卡，再做下一张。**不要一次贴三张卡。**

### 第 5 步：过关卡提交

- AI 自检：format / lint / type / test（它自己做，你不用重复）
- 你评审：只看"筛选逻辑是否符合真实意图""端点边界对不对""有没有改到范围外"
- 提交：`feat(order): support date range filter` + `Refs: REQ-023, TASK-101`
- 合并后：CHANGELOG 加一条

全程你没有翻过方案文档——只用了需求卡、任务卡、AGENTS.md、PR 模板这 4 个入口。

---

## 第一周只做三件事（别贪多）

1. 把 `templates/AGENTS.md` 复制到你的项目根目录
2. 每次开发先写一张需求卡，**哪怕只有 5 行**
3. PR 用固定模板

跑顺一周后，再依次加：CI 门禁 → ADR → 完整检查清单 → 度量看板。

> 为什么精益起步？因为规范的价值在于被执行，不在于完备。一套用起来的 3 条规则，胜过一套没人用的 30 条。

---

## 什么时候才需要翻详细方案

| 遇到这类情况 | 翻方案的哪部分 |
|---|---|
| 要定模块边界、技术选型 | 第三部分 3.2 ADR、附录 B2 |
| 有异议要判定谁说了算 | 第六部分 RACI 与红线 |
| 做里程碑验收、写复盘 | 第七部分度量与风险控制 |
| 新成员要知道全局 | 第一、四部分框架与追踪 |

日常开发，别翻。
