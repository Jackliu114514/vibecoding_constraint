# vibecoding-constraint

> 约束 — 让 Coding AI 的产出可追溯、可维护、可交接的一套工程约束规范。

这是一套 WorkBuddy Skill。它把"人 + AI 协作写代码"从随性的氛围编程，变成有契约、有关卡、有追踪的工程流程。

## 核心命题

**把 AI 的自由发挥，放进可追溯的工程契约里。**

三条不可妥协的原则：

1. 事实与推断分离——【原文/既有】与【分析结论，非原文】必须区分，推断不得伪装成事实
2. 单一事实来源——每类信息只有一个权威存放处，其他位置只引用不复制
3. 责任不可外包——AI 负责把事情做出来，人负责决定做什么、做到什么程度，并对结果签字担责

## 它能做什么

| 场景 | Skill 的响应 |
|---|---|
| 有一个模糊需求 | 触发复述—确认循环，先列歧义再动手，不确认不写代码 |
| 需求要落地 | 按 Epic → Story → Task → Prompt 拆解，生成原子任务卡 |
| 新项目要起步 | 自动铺 AGENTS.md + 模板 + 检查清单骨架（按阶段） |
| 要判断模板是否冗余 | 审计真实使用情况，给出降级建议而非盲目删除 |
| 要设计架构约束 | 起草 ADR，人拍板后生效 |
| 要评审代码 | AI 初筛格式与明显漏洞，人终审逻辑、边界与安全 |

## 结构

```
vibecoding_constraint/
├── SKILL.md                  # 核心工作流：任务路由 + 5 步流程 + 不可跳过的关卡
├── references/
│   ├── full-spec.md          # 完整方案：六层体系、质量保障、人机职责、度量与风控
│   └── daily-workflow.md     # 一页纸操作手册 + 完整走查示例
└── assets/
    ├── AGENTS.md             # AI 协作宪法，复制到项目根目录即可用
    ├── templates/            # 9 个模板：需求卡、任务卡、ADR、提交、PR、变更记录等
    └── checklists/           # 5 份清单：需求澄清、任务拆解、提交自检、评审、发布验收
```

另有 `scripts/`（见下），随 Skill 一同分发。

## 两个脚本

### scaffold.py — 铺设规范骨架

```bash
python scripts/scaffold.py <项目根目录> [--stage M2] [--dry-run] [--force]
```

- 默认不覆盖已存在文件——规范文件被团队改过后，静默覆盖等于抹除决策历史
- `--stage M0/M1/M2/M3` 按阶段铺设，避免一上来就被 9 个模板砸晕
- `--dry-run` 先看会动哪些文件

### audit.py — 审计使用情况

```bash
python scripts/audit.py <项目根目录> --stage M2
```

判断依据是模板**是否被实例化为真实文件**，而非"有没有被打开过"。输出四类结论：活跃保留 / 本阶段需补用 / 降级候选 / 未到阶段。还会检查 AGENTS.md 是否仍与原始模板完全一致。

## 安装

把本仓库放到 WorkBuddy 的用户级 Skill 目录：

```bash
git clone https://github.com/<你的账号>/vibecoding_constraint.git ~/.workbuddy/skills/vibecoding
```

注意目录名需与 `SKILL.md` 中的 `name: vibecoding` 保持一致。

触发词：vibecoding、氛围编程、AI 辅助开发规范、需求拆解、任务卡、ADR、AGENTS.md、代码评审规范、验收标准。

## 质量关卡

| 关卡 | 检查内容 | 执行者 |
|---|---|---|
| G1 需求 | 四要素齐全、验收可测 | 人 |
| G2 静态 | format / lint / type / 依赖安全 | AI 自动（CI） |
| G3 测试 | 单测、集成测试、覆盖率门槛 | AI 自动（CI） |
| G4 评审 | 逻辑、边界、架构合规 | AI 初筛 + 人终审 |
| G5 验收 | DoD 全满足、文档同步、变更已记录 | 人 |

## 人机职责

一句话判定原则：**AI 负责把事情做出来；人负责决定做什么、做到什么程度，并对结果签字担责。**

AI 不得单独决定的六条红线：需求范围变更、架构决策、生产合并、安全逻辑、技术债接受、缺陷等级判定。
